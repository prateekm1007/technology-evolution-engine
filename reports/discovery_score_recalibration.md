## Explanation

The score dropped from 9/10 (F1=0.9189) to 6/10 (F1=0.5714) because:

1. BRIDGE_SYNONYMS was removed in cycle 270 (F-158) because it was circular:
   19/20 gold bridges were direct keys, with synonym values
   reverse-engineered from extraction pipeline output.
2. The discovery_capability_score.json was NOT regenerated after the removal.
3. The scorecard (AUDITOR_SCORECARD.md) was NOT regenerated.
4. This left the repository in an internally inconsistent state:
   the code said BRIDGE_SYNONYMS = {} but the scorecard said F1=0.9189.
5. This sprint regenerated the score from source by execution.

## Commit that changed it
- Cycle 270 (F-158): removed BRIDGE_SYNONYMS (commit 808654d)
- This sprint: regenerated discovery_capability_score.json and AUDITOR_SCORECARD.md
- Current commit: f322df8ff281

## Why it changed

The _bridge_matches() function uses BRIDGE_SYNONYMS for semantic matching.
With the circular synonym map (19/20 gold bridges as keys), 17/20 gold
bridges matched (F1=0.9189). With the empty synonym map (non-circular),
only 8/20 gold bridges match via token overlap (F1=0.5714). The drop
of 9/20 matches is the exact number of gold bridges that were matching
ONLY through the circular synonym map — not through genuine discovery.
